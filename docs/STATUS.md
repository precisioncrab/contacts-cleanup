- **Test build 0.1.16: Manifest V2, and Repair.** The maintainer on 0.1.15: still slow; after the blue button the row still said "no chat address yet" and the right panel showed none; and Add JMP.chat addresses unchecked the contacts. Cause, in Thunderbird 158's `ext-addressBook.js`: in Manifest V3, `contacts.update(id, vCard)` and `contacts.create(parentId, vCard)` call `addProperties(card, vCard, ...)` with the vCard string, and `Object.entries` of a string is its characters, each saved as a custom property (`isCustomProperty` lets digit names through). Every write by 0.1.0 to 0.1.15 did it, and the properties stay (each update copies the old ones). The vCards themselves, and the servers, are fine (CardDAV syncs the vCard). Manifest V2 takes `{ vCard }`, a hidden property, so nothing extra is stored; and an update that sets those properties to null removes them (`SQLiteDirectory.saveCardProperties` rewrites a card's properties). So, the maintainer's choices: **Manifest V2** (`browser.contacts`, `update(id, { vCard })`, `create(parentId, null, { vCard })`, `browserAction`; `src/lib/addressbook.js` explains it), and **Repair**: a bar at the top of every page while any writable card carries such properties, which clears them card by card (`api.repair`: the same vCard, the leftovers set to null); Thunderbird uploads the synced cards again.
