# Plan

_Created 2026-10-18. Chat addresses and the split with the OMEMO add-on and Daynizer decided 2026-10-19. First build 2026-10-20: the open questions are answered under "How it's built"._

## Goal
A free add-on on addons.thunderbird.net (ATN) that cleans up Thunderbird's address book and adds chat addresses to contact cards. It also helps people find OMEMO for Thunderbird, which ATN can't list: that add-on needs a WebExtension Experiment (Thunderbird has no official API for its chat), and ATN rejects add-ons with Experiments.

Kept separate from Daynizer's add-on (decided 2026-10-19): its own ATN listing is how people find it, it works on Thunderbird's own address book (Daynizer's add-on keeps its own CardDAV contacts), and a small free add-on is easier to trust. Daynizer gets the chat address features in its own screens.

## Rules
- Official Thunderbird WebExtension APIs only, never an Experiment.
- Manifest V2 (from 0.1.16), not V3: Thunderbird 158's V3 `contacts.update` and `create` store every character of the vCard as a property on the card (see `src/lib/addressbook.js`). Back to V3 only once Thunderbird fixes that.
- The user sees every change before it happens, and every applied change can be undone.
- MPL-2.0, no copyleft code.

## Where it runs
Its own tab, opened from a button in the spaces toolbar (Thunderbird's left sidebar, as Daynizer has; added 2026-10-20 at the maintainer's request), a toolbar button or the Tools menu; all three open the same space tab. The official API can't add anything inside the address book itself: no right-click on cards and no button in the address book's toolbar (checked in Thunderbird 158's API schemas, 2026-10-19: the menu contexts are mail, compose, folders, tabs and the Tools menu; toolbar buttons go on the main or tabs toolbar). Buttons in this tab do what a right-click would.

## Layout (0.1.13, decided by the maintainer 2026-10-21)
Like Daynizer's Contacts tab (to be brought into Daynizer once the maintainer is happy with it): a sidebar in Daynizer's order (0.1.14): **Contacts** (All contacts), **Address books** (a checkbox per book: the books every page looks at; no sync arrows, since Thunderbird doesn't tell add-ons which books sync over CardDAV), **Labels** (the labels in use), **Clean up** (Duplicates, Phone numbers, Missing names), **Chat** (Chat addresses, and the OMEMO button: Get OMEMO for Thunderbird with nothing installed, Get OMEMO Pro with the free one, OMEMO settings with Pro), **More** (Changes, About). Each category folds away (remembered). The right-hand panel is the selected contact's editor on every page that lists contacts. Everything is free; OMEMO Pro is only calls.

## Features
0. **All contacts:** search, + New contact, Import vCard (into a book picked in the question; the cards' UIDs left out so they're never refused as taken), and the editor (`src/ui/contact-panel.js`, fields from `src/core/card-model.js`): address book (changing it moves the contact: a copy there and a delete here, undone together, since Thunderbird has no move for add-ons), display name (from first and last name when left empty), first and last name, nickname, organization, title, birthday and anniversary (date pickers, "no year"), phones and emails with Daynizer's types, chat addresses ("+ JMP.chat address for" each number, and "In chat list" on each address when OMEMO for Thunderbird can add people), addresses, websites, labels (CATEGORIES, with the labels in use to pick from), notes; Save and Delete, both undoable. A field the user didn't change keeps its vCard lines exactly; a changed value keeps its line's group and parameters. Edits stay per contact until saved ("Undo my edits" drops them).
1. **Duplicates:** potential duplicates are cards in the same address book with the same email, phone number, XMPP address or name. The merge works like Outlook on the web's: the user checks the cards that are the same person, picks the card to keep and what the merged card has (every detail editable: display, first and last name, organization, job title, nickname, and each phone number, email, address, website and chat address, with phone numbers, emails, addresses and websites addable; 0.1.5, the maintainer; and which card's photo it keeps, 0.1.6), and clicks Merge. One merge at a time; unchecked cards are left alone, and if they still look like duplicates the page stays on them. Delete on a card removes just that card (0.1.4, the maintainer). The cards that look most alike start checked (strong matches only: the same email or chat address, or the same phone with a matching first name, or the same full name; names that clash are never checked together); none when nothing is a strong match. "Not duplicates" hides a group for good. A checkbox compares across address books too (off by default: Google Contacts won't merge across accounts, Apple Contacts links such cards). **How it got here (2026-10-20, the maintainer):** 0.1.0 merged a whole group or nothing; 0.1.1 and 0.1.2 sorted a group into people (pickers, then columns) and merged them all with one Apply, which the maintainer found confusing; 0.1.3 is the simple check, keep, Merge flow the maintainer described.
2. **Phone numbers:** one format (international, `+1 555 123 4567`), with a default country for numbers without a country code (10-digit numbers read as US/Canada by default).
3. **Missing names:** a display name from the first and last name, or from the email address. The editor on the right shows the whole card.
4. **Chat addresses** (the one Chat page, 0.1.13), two tabs:
   - **Contacts:** every contact with a phone number or chat address (`chatRows`): its chat address, or "number -> JMP.chat address" with "no chat address yet" (`xmpp:+15551234567@cheogram.com`, which lets an XMPP account registered with JMP.chat text and call that number; gateway `cheogram.com` by default), and "in chat list". Checkboxes and Select all; the bar offers **Add JMP.chat addresses** (to the checked cards without a chat address) and **Add to chat list** (asks first; a card without a chat address also gets the JMP.chat address it's added with). Chat addresses Thunderbird can't use (no `xmpp:`, X-JABBER) show in a bar at the top with Show and Fix all. Filters: all, without a chat address, not in the chat list, to fix.
   - **Chat list:** through OMEMO for Thunderbird: per account "Names from your address book" (Off, In Thunderbird only, In Thunderbird and on the server) with Name it now; **No name yet:** chat contacts no card has, each with Add to a card (the card gets the number for a JMP.chat or Quicksy address, since OMEMO matches those by number only, else the chat address) and New card; the named ones folded.
   - Adding to and taking off the chat list is OMEMO for Thunderbird's (free from 0.1.6; OMEMO Pro 0.3.4): a roster set with the card's name and a presence subscription, or a roster remove.
   - History: 0.1.10 had separate Chat addresses and Chat contacts pages, which the maintainer found confusing; 0.1.11 made one Chat page and dropped the JMP.chat list; 0.1.12 brought that back under Clean up; 0.1.13 is this layout, the maintainer's design.

## Help text (needed on the Chat addresses and Chat contacts tabs)
Plain explanations of what each choice means, since there are two different servers involved:
- **Chat address on a card:** saved with the contact, like an email address. It goes wherever that address book syncs (your CardDAV server, then your phone and other apps), or nowhere for a local address book. On its own it doesn't add anyone to a chat list.
- **JMP.chat address:** a phone number at `cheogram.com`. It only works if your XMPP account is registered with JMP.chat (or uses another Cheogram gateway); then texts and calls to it reach that phone number as SMS and phone calls.
- **Chat contact, Thunderbird only:** the person shows in Thunderbird's chat list. Your XMPP server and your other chat apps don't see it.
- **Chat contact, also on your XMPP server:** added to your account's contact list on your XMPP server, so every chat app signed in to that account shows it too.
- What happens when a chat address or a chat contact is removed.

## How it's built (2026-10-20)
- **Manifest V3, Thunderbird 128 and later.** Checked in Thunderbird 158's own schemas: in MV3 the card API is `addressBooks.contacts`, and `update(id, vCard)` and `create(parentId, vCard)` take vCard text; a card node carries `vCard`. Permissions: `addressBooks`, `menus` (Tools > Contacts Cleanup), `storage`. No host permissions, no network.
- **Editing a card without losing fields:** Thunderbird replaces a card's whole vCard on update, so the add-on never rebuilds a card from a model. It edits the vCard line by line (`src/core/vcard.js`): untouched lines go back byte for byte (photos, custom fields, Apple's grouped labels), and a changed value keeps its line's parameters (type, PREF) as written.
- **Merging:** the kept card is edited; the others are deleted. Values from the other cards are added without their group (an Apple `item1.` label would point nowhere) and without PREF (the kept card's preferred values stay preferred). Fields only the other cards hold are added; categories are joined. The default kept card is one with a photo, else the one with the most fields; the default name is the fullest one.
- **Photos (0.1.6):** Thunderbird puts a card's photo in the vCard it gives add-ons (for local address books it adds the photo file as a `PHOTO` data URL; read in Thunderbird 158's `ext-addressBook.js`), so avatars show it from there, with `getPhoto` as the fallback for a photo that's only a web link. A merge can give the kept card another card's `PHOTO` line. An update with the `PHOTO` line keeps the photo (it goes into the card's stored vCard).
- **Undo:** each applied change is a history entry with every card's vCard before and after (read back from Thunderbird), and a deleted card's photo when its vCard has none. A change that leaves a card's photo alone stores both vCards without it and undo puts the card's current photo back, so a batch change doesn't store every photo twice; comparing for conflicts ignores the photo. Undo checks nothing changed since (REV and PRODID aside, so a sync doesn't count) and asks before overwriting. Deleted cards come back with their old UID, so they keep their id. The last 50 changes are kept.
- **Phone format:** US and Canada numbers are always `+1 555 123 4567`. Other countries' numbers keep the digit grouping the user typed (each country groups its own way); one written as a single block gets a simple grouping. The compact format is plain +E.164. Numbers with an extension, or without a country code when none is picked, are left alone and listed.
- **Generated chat addresses** are tracked per card id (`generated` in storage), so only those are ever removed; undo keeps that record in step.
- **UI:** plain DOM, no framework and no build step, so the package is the source ATN reviews. Daynizer's color tokens (dark and light), sidebar, toolbar, rows, detail panel and menu bar; View > Theme with Match System (follows Thunderbird's theme), Light Mode and Dark Mode, as in Daynizer.
- **Chat contacts protocol (OMEMO for Thunderbird's `runtime.onMessageExternal`, answering only `contacts-cleanup@precisioncrab`):** `hello` -> `{ name, version, pro, protocol: 1 }`; `chatNames.preview` -> the same result its options page shows; `chatNames.setMode { jid, mode }` saves the account's choice (`off`, `local`, `server`) and writes; `openOptions { section }`. Without an answer (not installed, turned off, or older than 0.1.5) the tab explains and links to it. Telling those apart would need the `management` permission, which isn't worth asking for.
